📊 Shareholding Pattern Alerts

Every day at 16:35 IST (right after the MF holdings check) the server pulls the latest 12 quarters of shareholding-pattern data from Trendlyne for your 8 stocks and emails you when anything changes above the significance threshold (Promoter ≥0.1%, FII/DII/MF/Banks/Insurance/Public/Others ≥0.5%). Shares the same SMTP creds as the MF alerts.

    Telegram setup
    

      
To enable real Telegram delivery:

      
    
        
  1. Open a chat with @BotFather on Telegram
    2. 
        
  2. Send /newbot and follow the prompts (give it a name like "Portfolio News Bot")
    3. 
        
  3. BotFather will give you a token like 123456:ABC-DEF...
    4. 
        
  4. Open a chat with your new bot and send /start
    5. 
        
  5. Find your chat_id by visiting https://api.telegram.org/bot<TOKEN>/getUpdates in a browser (look for the numeric chat.id), or message @userinfobot
    6. 
        
  6. Add to .env:
          
    NEWS_TELEGRAM_BOT_TOKEN=your-token-here
NEWS_TELEGRAM_CHAT_ID=your-chat-id-here
NEWS_DRY_RUN=0
    
        
    7. 
        
  7. Disable with NEWS_DISABLED=1 when starting the server
    8. 
      

    

  






  
📧 Mutual Fund Alerts

  

    Every day at 16:30 IST (just after market close) the server checks
    Trendlyne for changes in MF holdings of your 8 stocks. If anything
    changed, you'll get an email with a per-stock diff. If you have no
    SMTP credentials configured, the alert runs in "dry-run" mode and
    just logs the email body.

    SMTP setup
    

      
Set these env vars (or add them to secrets.local.json):

      
    
        
  • MF_ALERT_SMTP_HOST e.g. smtp.gmail.com
    • 
        
  • MF_ALERT_SMTP_PORT e.g. 587
    • 
        
  • MF_ALERT_SMTP_USER your full email address
    • 
        
  • MF_ALERT_SMTP_PASS app password (Gmail users: create one at
            myaccount.google.com/apppasswords)
    • 
        
  • MF_ALERT_TO recipient (defaults to SMTP_USER)
    • 
        
  • MF_ALERT_DRY_RUN 1 to log instead of send
    • 
      

      
Disable the scheduler with MF_ALERT_DISABLED=1 when starting the server.
